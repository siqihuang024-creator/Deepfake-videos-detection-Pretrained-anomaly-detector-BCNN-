# GenD-PE 检测器实验方案（第一阶段）

定稿日期：2026-11-12。本文件在看任何测试结果之前写定。之后若要改动，在文末"变更记录"里写明日期、改了什么、为什么改，以及改动时看过哪些结果。

整体分两个阶段：

- **第一阶段（本文件）**：用真假视频监督训练 GenD-PE，得到能分辨真假的检测器。
- **第二阶段（以后另写）**：接上贝叶斯 NN，只用 Celeb-DF v3 训练集的真视频训练整个模型，变成异常检测器。

## 0. 两套协议，各管什么

这一节是全文的总规则。**哪一部分跟 GenD 走、哪一部分跟旧协议走，在每一步里都不变。** 下文各步只写例外。

| 方面 | 跟谁一致 | 具体内容 |
| --- | --- | --- |
| 模型结构 | **GenD** | PE-L/14（`vit_pe_core_large_patch14_336`），输入 224；头是 LinearNorm（L2 归一化后接 Linear(1024, 2)） |
| 可训练参数 | **GenD** | 只训练 `norm_pre`、`norm1`、`norm2`、`norm` 和线性头 |
| 损失函数 | **GenD** | 交叉熵 + 0.5 × uniformity + 0.1 × alignment（配置 `wacv-PE_L-LN+L2+UnAl`） |
| 优化器和学习率调度 | **GenD**（以代码为准） | AdamW，wd 0；lr 3e-4、最低 1e-5；batch 128；开头预热 1 个 epoch；cyclic cosine，每 10 个 epoch 一个周期；最多 30 个 epoch；bf16-mixed |
| 数据增强 | **GenD** | `config.Augmentations` 的默认值 |
| 人脸预处理 | **GenD** | RetinaFace（`det_10g.onnx`），检测阈值 0.5，NMS 0.4，取面积最大的人脸，按 5 点关键点对齐，外扩 1.3 倍，缩放到 224×224，保存为 PNG（无损） |
| 抽帧 | **本项目固定协议**（参考 GenD 配置目录名） | 先对每一帧做人脸检测，再从**检测成功的帧**里抽：训练集**随机**抽 32 帧，验证集和测试集**均匀**抽 32 帧。成功帧不足 32 就全部使用，不重复补帧；不等同于官方 `fixed_num_frames` |
| 视频分数 | **GenD** | 各帧 softmax 后"假"的概率取平均 |
| 标签约定 | **GenD**（内部） | 真 = 0，假 = 1。旧清单是真 = 1、假 = 0，转换时显式映射，并按 GenD 自己的路径规则逐个视频反查核对 |
| v3 视频的划分（第一、二步） | **旧协议** | `protocols/celeb_video_disjoint_seed42/group_XX.csv`，是从旧项目原样复制的，SHA256 记录在同目录的 `SHA256SUMS`；只用第 01–30 组 |
| 训练集 | **旧协议**（第二步） | 每组 616 真 + 616 假 |
| 验证集 | **旧协议**（第一、二步，以及第三步在 v3 上的评估） | 固定 134 真 + 134 假，30 组共用 |
| 测试集 | **旧协议** | 固定 133 真 + 133 假，30 组共用；上一轮已经看过结果，报告时称为"沿用旧协议的固定对比测试集" |
| 每组的随机种子 | **旧协议** | 第 g 组用 41 + g |
| 挑 checkpoint 和挑组 | **旧协议** | 每组内按验证集视频级 AUROC 挑最佳 epoch，30 组之间再按同一指标挑一组；测试集不参与任何选择 |
| 报告的指标 | **旧协议** | AUROC、按身份和按源视频聚类的 bootstrap 95% 区间、AP（假为正类、真为正类、两者平均）、EER、5% FPR 下的 TPR、两个工作点（阈值见下一行）下的准确率、平衡准确率、混淆矩阵、"假"类的精确率/召回率/F1；同时报告按方法分开的结果 |
| 阈值 | **旧协议** | 主阈值取验证集真视频分数的 95% 分位数（即 5% FPR）；另报固定阈值"假的概率 ≥ 0.5"。阈值不能在测试集上重新校准 |

### 和两套协议都不一致的地方（有意为之，逐条说明）

1. **训练轮数用 GenD 的 30 个 epoch，不用旧协议的 100 个。** 训练方法要和 GenD 完全一致；旧协议的 100 epoch 是针对 3D-CNN 定的。GenD 的早停 patience 是 30，等于最大 epoch 数，所以实际上不会提前停。
2. **挑 checkpoint 的指标改成验证集视频级 AUROC**，不用 GenD 默认的 `val/mAP_video`。原因是要和旧协议的选择规则一致。GenD 的验证集还混入了 DeepSpeak 和 FFIW，我们不用，第一、二步只用旧协议的 268 个验证视频。
3. **训练集抽帧只用一个固定种子。** GenD 论文每个 seed 各自随机抽一次帧（`split-0` 到 `split-4`）；我们的 30 组本身就是重复实验，所以所有组共用一份训练帧（抽帧种子 0）。真视频在不同组里重复出现时，用的是同一批帧，30 组之间的差别只来自伪造训练视频和训练种子。这样也省下大量存储。
4. **旧协议的人脸预处理（dlib 对齐、margin 0.5、32 帧连续片段）和 3D-CNN 的训练设置在这里都不用**，统一换成 GenD 的做法。和旧 3D-CNN 结果（第 19 组测试 AUROC 0.7671）比较时，比的是"整套方法"在同一批视频上的端到端效果。

### 抽帧规则的细节

- 抽帧种子是按每个视频固定下来的：由"全局种子 + 视频相对路径"算出，与运行顺序无关。
- 均匀抽帧：在检测成功的帧序号列表上用 `np.linspace(0, n-1, 32)` 取位置并四舍五入，再去掉重复。
- 每个视频都记录这几项：总帧数、检测成功的帧数、实际用了几帧、用了哪些帧号。
- 一张人脸都没检测到的视频不能打分，单独列出来，并报告各模型的覆盖率。各模型之间只在**都能打分的视频**上比较。

这个流程参考了官方目录名（`...-all/subset/random-32-frames`、`uniform-32-frames`），不能声称严格复现。GenD 已公开人脸预处理和抽帧代码；在核对的上游提交 `387a422` 中，未定位到生成上述特定随机/均匀子集的独立脚本，目录名本身也不能确定取样发生在检测之前还是之后。

论文第 3.2 节描述先在原视频上均匀取 32 帧再检测人脸。官方 `detector.py` 的 `fixed_num_frames` 使用 `np.linspace(..., dtype=int)` 在原视频帧号上取样；本项目在检测成功的帧列表上取样并四舍五入。检测失败时两者的候选集合不同；即使没有检测失败，整数取样与四舍五入也可能选出不同帧号。官方 README 示例的 `at_least` 则是第三种模式，不能与前两种规则混称。

本项目每个视频最多使用 32 张单帧图像，没有“8 个 clip × 32 帧”的输入。Slurm 的 8 个分片只划分待处理视频。若后续改用其他抽帧规则，须记录为新的协议版本并使用独立的预处理目录。

## 1. 第一步：官方 FF++ 权重直接评估

- 权重：`yermandy/GenD_PE_L`，不训练。
- 数据：旧协议的固定验证集，先只跑验证集。测试集等第二步选出模型后，和其他模型一起统一评估一次。
- 只跑一次。验证集和测试集在 30 组里都一样，这一步又不训练，所以 30 组的结果会完全相同。
- 称呼：**"未在我们的 v3 训练集上继续训练的官方 FF++ 权重"**，不叫"零样本"。官方挑 checkpoint 时用过 CDFv3 的验证数据。
- 附带检查：官方用过的 CDFv3 验证视频列表（HF 数据集 `yermandy/GenD`）和我们的 266 个测试视频有没有重叠。

## 2. 第二步：从官方权重开始，在 v3 上按 GenD 方法微调

- 初始权重：`yermandy/GenD_PE_L`，装进可训练的 GenD 模型。
- **先核对权重加载是否正确，再开始训练**：用同一批人脸图，分别输入官方推理模型和装好权重的可训练模型，两者的概率差不超过 1e-3（bf16 下放宽到 1e-2）。同时检查有没有漏载的参数、头有没有被重新初始化、"假"的概率是不是第 1 列。
- 训练数据：第 g 组 CSV 中 `split == train` 的 616 真 + 616 假。
- 验证：固定的 268 个验证视频，每个 epoch 都评估。
- 训练时**不传入测试清单**，也不调用官方 `run.py`。官方 `run.py` 训练完会自动在测试集上测试，我们的训练脚本只调用 `fit`。
- 流程：
  1. 先用第 01 组跑通。调试阶段不看测试指标，调试结果也不用来改超参数，超参数只按 GenD。
  2. 再跑满 30 组。
  3. 每组保存最佳验证 AUROC 的 checkpoint。
  4. 按验证 AUROC 选出一组。
  5. 对选中的这一个模型评估一次测试集。
- 报告：30 组最佳验证 AUROC 的均值、标准差、中位数和范围；选中组的验证 AUROC 和最佳 epoch；该模型的测试结果。30 组之间相关性很强，不能当作 30 次独立的测试估计。

## 3. 第三步：从原始 PE 开始，用更大规模的数据训练

开始前还要另行定稿的内容见 3.3。下面是已经定下的部分。

### 3.1 训练两组

- **只用 FF++** 一组，**FF++ + DeepSpeak** 一组。
- 两组都从原始 PE 权重开始（timm 预训练，不加载 GenD 权重），训练方法完全相同（第 0 节）。
- 两组用同一份验证集挑 checkpoint，采用固定的 FF++ 验证集（官方划分）。v3 不参与训练，也不参与挑 checkpoint。
- 自己训练的"只用 FF++"组可以和官方权重并排给出，作为复现情况的参考。但两者挑 checkpoint 的方式不同，结果接近只能说明表现接近，不能说明复现完全一致。

### 3.2 数据划分

- **跟 GenD / 各数据集官方一致**：FF++ c23 按官方 train / val / test 划分（720 / 140 / 140），DeepSpeak 按官方划分。
- **在 v3 上评估时跟旧协议一致**：用同样的 268 个验证视频和 266 个测试视频，指标也按旧协议计算，便于和第一、二步比较。
- 5% FPR 的阈值有两种定法，都要报告：
  - 在 v3 验证集上定：注明"阈值在目标域校准"；
  - 在 FF++ 验证集上定：注明"阈值在源域校准"。

  AUROC 不依赖阈值。

### 3.3 第三步开始前还要定的

- 用 DeepSpeak 的哪个版本（v1.1 / v2），具体用哪些划分。
- 真假样本怎么平衡：GenD 原本在 FF++ 上是 1 真 : 4 假，没做平衡。两组要用同一种平衡方式，否则训练数据和平衡方式会同时变化。
- 混合训练时各数据集的采样比例，以及优化步数怎么对齐。
- 种子：GenD 跑了 5 个种子（0–4）报告均值 ± 标准差。我们先跑种子 0，要不要补满 5 个之后再定。

## 4. 第四步（第二阶段）

接上贝叶斯 NN，只用 v3 训练集的真视频训练整个模型。训练目标、异常分数和防塌缩措施以后另写方案，不在本文件范围内。

## 5. 测试集使用规则

- 266 个测试视频只用于最终比较。每个模型都是按上面的规则选出来之后，再评估一次。
- 评估脚本会检查：被评估的 checkpoint 是否就是选择记录（`selection.json`）里写的那一个；阈值是否来自验证集。不满足就拒绝运行。
- 不能用测试结果去挑组、挑 epoch、改超参数或改预处理。
