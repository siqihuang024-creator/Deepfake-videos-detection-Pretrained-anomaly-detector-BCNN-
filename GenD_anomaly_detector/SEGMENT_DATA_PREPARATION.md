## 本阶段固定范围与预算

- 保留原整视频 train/calibration/dev/test 来源组划分；source_only 仅表示已有来源组隔离，不能声称人物隔离。
- A 为 HDTF、TalkingHead-1KH 的原 train/calibration 来源组。每个全局来源组按 seed 42 的路径哈希选一个原视频，最多生成 4 个 10 秒中段候选，避免同一来源多个文件或长时长主导数量。原 train/calibration 不交换，也不从 dev/test 补入。
- 开发诊断先取 DFDC dev 的 100 个可配对来源组，每组一个真实文件、一个伪造文件，共 200 个视频；来源组和文件均按预先固定哈希选取。其余 dev 仍标为未使用的开发数据，不能改称最终测试。
- 所有原始 test 元数据保存为 reserved_test.csv；不生成它们的候选，不解码、不看图、不提特征或评分。PolyGlotFake 保留在这里。
- 候选总数硬上限 3,000；超过上限先报错，不自动扩充任务或改变数据角色。实际数量由远程完整时长表决定，不保证达到上限。
- 检测固定为 pad_on_empty_v1，0.5 阈值、0.4 NMS、640 输入；224×224 人脸图，每候选最多均匀选 32 帧。维持原五格覆盖诊断标记，但保留所有窗口和失败记录；本阶段不按标记发布训练样本或过滤测试结果。

当前原清单共 573 个 A train 原视频、133 个 A calibration 原视频。它们分别含约 455、115 个已有来源组。来源组限额会减少重复来源原件的处理数量；程序报告实际入选原视频、来源组、候选数，不把片段数当成独立人物数。

## 登记与运行

从仓库根目录执行；先更新代码。`--reference-pilot` 使用已目视核查的中段试跑登记。程序核对原 CSV、时长审计及参考试跑的哈希，检查入选原视频的实际大小和 mtime，并将父表、选中原视频、保留测试元数据和未使用开发元数据全部存入新目录。

```bash
py=work/.venv-gend/bin/python
"$py" GenD_anomaly_detector/scripts/prepare_segment_data.py \
  --manifest "$HOME/gend_steps34_manifest_pilot.csv" \
  --duration-audit work/video_duration_audit_279 \
  --reference-pilot work/segment_interior_10s_20261125_222208/segment_pilot.json \
  --video-root /data/datasets/shuang --out "$DATA_PREPARATION" \
  --dev-source-groups 100 --max-candidate-clips 3000 --seed 42

sbatch GenD_anomaly_detector/slurm/segment_data.sbatch \
  "$DATA_PREPARATION/segment_data_plan.json" "$DATA_PREPARATION/faces"
```

GPU 任务申请 1 GPU、4 CPU、16 GiB 内存，时间上限 8 小时。这是调度上限，不是耗时预测。小批观测支持小时级而非分钟级的扩大准备，实际速度还受视频尺寸、关键帧间隔、存储 I/O、功率和节点负载影响。先处理有界候选及 200 个开发视频，而非全量三万余测试视频。

日志为 `work/logs/gend_segment_data_<jobid>.out`，每个候选显示进度；结果写入 `faces/pilot_summary.json`、`pilot_measurements.csv`、逐片段 records/detections/crops。每个已完成窗口有独立原子记录。错误会被汇总并以非零状态退出；修复原因后可在同一命令末尾添加 `resume`。恢复必须使用同一代码、运行时、文件、检测政策和登记；代码/输入有变化则用新目录。

后续将根据实际覆盖和抽查结果确定每个来源最多保留的训练片段数、校准/评估单位及质量处理规则，然后生成冻结特征缓存并训练第三/四步的贝叶斯头。测试集必须等方法及这些规则锁定后才打开。

## 等待 GPU 时可并行完成的训练底层

本地新增 `bayesian_svdd.fit_source_balanced`：每个给定来源组总权重相同，组内各片段平分该组权重；输入中心、初始特征方差和 SVDD 中心、数据损失、早停指标及训练诊断使用对应权重。KL 项以显式来源组数作为归一化分母，保存分组数量及训练/早停权重。它是预先声明的均衡代理目标，不把同源片段变成独立观察，也不保证后验已校准。拟合和早停出现相同来源 ID 时直接拒绝。

另新增 `score_grouped`，支持视频内等权或显式正权汇总。每次抽取同一个网络用于所有片段，在该次抽样内先汇总视频分数，然后计算跨抽样的均值和方差，以保留片段之间的共同权重不确定性；不能直接平均各片段的方差当作视频方差。输出为均值距离和距离的后验方差，不是“为假的概率”。

两个 API 在 CPU 合成特征上测试，不需要远程 GPU。旧 `fit/score` 默认行为保留；原整视频 CLI 还未自动切到这些新 API。正式片段选择、组 ID/权重、视频汇总方式及校准单位必须在接入口时明确登记，不能只改函数就认为步骤 3/4 已经完成。作业 301 的预处理代码、登记和输出目录不因此改变；这些本地改动尚未推送时也不影响远程作业。

## 作业 301 后的候选特征缓存

`prepare_segment_cache.py` 接收已完成的 `segment_data_plan.json` 和 `faces/`，核对登记表、预处理合同、逐片段记录、PTS 及裁剪文件存在性，另建不可覆盖的帧清单。它保留所有有裁剪的候选，包括低覆盖窗口；无脸窗口保留在未评分清单和分母中。不按分类概率或贝叶斯分数筛选，也不打开保留测试视频。此清单仅用于缓存，不是正式训练/校准规则。

`slurm/segment_features.sbatch DATA OUT SELECTION` 申请单 GPU、8 CPU、48 GiB、最长 2 小时，以 bf16、batch 256、8 workers 顺序运行官方和选定微调编码器。原人脸图不重做、编码器不训练。缓存保存逐帧特征、时间戳、分类概率和片段均值；两套路径分别记入 `OUT/cache_receipts/{official,finetuned}.json`。耗时以实际日志为准，2 小时为调度上限。该脚本要求新 OUT；失败后不要重新提交同一路径，已完成特征可由底层提取脚本复用，先检查日志。

本地对 301 元数据的核查：2,362 个候选、72,587 张选中图片；2,137 个达到诊断覆盖条件。训练候选中 1,548 个覆盖标记通过，涉及 440 个来源组；校准 389 个涉及 112 个来源组；开发 200 个真假配对片段涉及 100 个来源组。覆盖标记不代表语义质量保证；下载包未含图片/检测数组，图片存在性由远程准备缓存清单时检查。正式来源均衡训练入口仍需接通，不能将新缓存误传旧整视频 CLI。

## 作业 311 后的贝叶斯训练入口（已接通）

`train_segment_bayesian.py` 和 `slurm/segment_bayesian.sbatch` 在 CPU 上读取两套现有缓存，先为两个编码器共同登记清单及配方，再依次训练；不加载 GenD 模型，不提新特征，无最终测试入口。旧整视频入口保持原样。

- A 训练/校准只采用已登记持续覆盖标记通过且有 32 张选中图片的窗口。固定 seed 42 的窗口键哈希排序，每个训练来源最多 2 个窗口，每个校准来源恰取 1 个可用窗口；不按概率、异常分数或检测置信度优选。此质量条件会改变 A 的分布，报告保留被排除来源和片段的分母，不宣称对任意真实视频的误报保证。
- 训练角色内按已有来源/所提供身份的连通组留出 20% 早停。拟合和早停分别使用来源均衡权重，KL 除以拟合来源组数；这是均衡代理目标，不把同源片段当成独立人物。
- 开发角色仍使用每个视频已登记的一个窗口。只要有裁剪即可评分，保留低覆盖窗口，不采用 A 的持续覆盖条件过滤开发视频；无脸视频保留为不可评分。校准和开发均为一个窗口一个分数，最多均匀 32 帧，缓存片段特征为逐帧 L2 特征的均值。
- 按 301 元数据预览：拟合 679 片段/352 来源，早停 169/88，校准 112/112，开发 200 视频/100 配对来源。正式数量以远程实际缓存/记录验证后写出的 `training_registration.json` 为准。
- 结构 1024→512→128，无偏置，batch 128 个特征向量，Adam lr=1e-3，KL 权重 1e-3；最多 100 轮、patience 12。早停 8 次权重抽样，评分 50 次；距离均值作异常分数，距离后验方差作未校准的不确定性。仅 seed 42，为初始主线，尚未做多种子或非贝叶斯对照。
- 两套头各自在同一独立真实校准单元上取 95% 和 99% 分位数阈值；GenD 分类概率也用对应的真实校准单元定阈值。112 个校准来源意味着经验误报率分辨率约 0.89 个百分点，名义 1%/5% 不保证在 DFDC 成立。
- 输出：共同 `training_registration.json`、`training_units.csv`；两套 `head.npz`、训练历史/实时进度、校准/开发分数、误报清单、分来源误报率及区间、坍缩诊断、`development_lock.json`；总表 `comparison.csv` 和完成标记 `completion.json`。开发锁是后续评价的快照，不是最终测试成绩。若坍缩标记出现，不能将该头当作成功的鉴别器。

提交格式：`sbatch GenD_anomaly_detector/slurm/segment_bayesian.sbatch DATA CACHE_RUN SELECTION NEW_OUT`。申请 4 CPU、16 GiB，以 `--time=0` 请求无限运行时间（以集群策略允许为准），不申请 GPU。第三/四步使用完全相同的单元和训练规则，区别为冻结编码器及其缓存。保留第二步结果；不同数据集上的数字不能直接解释为相对第二步的提升。
